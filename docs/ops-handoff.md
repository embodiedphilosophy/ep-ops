## 1. What the dashboard is for

One place for EP staff, contractors and rotating teachers. Every screen answers one question:

| Place | Question | Who |
|---|---|---|
| Today `/ops` | What needs me this week? | everyone (scoped) |
| Events `/ops/events` | Is each offering ready? | everyone; editors change |
| Tasks `/ops/tasks` | The whole task list | staff |
| Publish `/ops/content` | Is everything we publish moving? | staff |
| Business `/ops/insights` | Is EP healthy? | director |
| People `/ops/team`, Hours `/ops/hours` | Who does what; time worked | staff |
| Settings `/ops/settings` | Every sheet-backed table | director + editors (manager, projects) |
| Landing Pages `/ops/landing` | Is every /lp/ page live and its checkout working? | staff |

## 3. Architecture map

- `app/ops/Shell.js` sidebar + page header (`title`, `eyebrow`, `head`). `lib/ops/nav.js` who sees which item.
- `app/ops/ops.css` the design system. Scoped to `.ops-shell` (and `.ops-login`) because `/teach` reuses `ops-*` class names. Old ops rules in `app/globals.css` are overridden, not yet deleted.
- Tasks: always import from `lib/ops/taskstore.js` (never `motion.js` or `taskdb.js` directly). Shape: `{ id, name, description, due, labels[], completed, blockedOn, auto }`. Owners are labels (a person's name or a role). Conventions kept in `description`: `[ep:EVENTID:task-slug:owner-slug]` event tag, `[blocked:Name]`, `[auto:date:rule]`.
- `lib/ops/tasks.js` task logic (expected tasks from Task Templates, `visibleTo`, `forHome`, `bucket`, `groupByEvent`, `needsOwner`). `syncToMotion()` is a legacy name; it writes to the task store.
- `lib/ops/hours.js` time clock (Neon tables `ops_shifts`, `ops_hour_requests`, `ops_hour_alerts`; made on first use).
- `lib/ops/landingpages.js` + `app/ops/landing/` Landing Pages: reads ep-website's `/api/landing-pages` (5-min cache, `LANDING_PAGES_URL` overrides), derives Upcoming/Running/Ended/Evergreen from `startsAt`/`endsAt` (New York dates), checks each page (must answer 200) and checkout link (2xx) with a 5-min per-instance cache (`?check=1` forces a fresh check), links to the Course Library when the slug matches an offering id. Stores nothing.
- `lib/ops/store.js` the only safe writer to the calendar sheet (by header name, refuses formula columns, conflict check, Change Log). Use it for any sheet write.
- `lib/ops/sitetables.js` + `app/ops/content/SiteEditor.js` the table editor behind Settings (`scope="settings"`).
- `lib/ops/checks.js` + `lib/ops/readiness.js` event readiness checks.
- Crons (`vercel.json`): `/api/ops/daily` 13:00 UTC (task sync, reminders, nudges, Motion digest), `/api/ops/auto` every 15 min (auto-complete, shift sweep).
- Root `ops/` folder (`ops/motion.js`, `ops/tasks.js`) is an old copy, not imported by the app. Confirm and delete.

## 4. Rules (keep these)

- The Google Sheet (EP-Programming-Calendar) is the source of truth for events and settings; the database holds tasks, hours and decisions. Never keep a second checklist.
- Design: terra `--risk` only for late/at risk; pine `--pine` for actions; status is always a dot + a word; 44px rows; one section-header style; underline tabs; detail in a drawer; help text sparingly. No emoji, no new fonts, no gradients.
- Dates are New York time (`todayET()`; `America/New_York` client-side).
- Teacher reminder emails go only to the addresses in that session's Teacher/Host Emails column. Never widen this.
- Automated emails go from "EP Admin" <team@embodiedphilosophy.com>.
- Copy: plain, short, sentence case. Name things the user knows (Master Schedule, Kit, Circle).
- Next.js here is a new major version: check `node_modules/next/dist/docs/` before using unfamiliar APIs.

## 10. YouTube Studio (Nov 2026, branch `claude/youtube-studio`)

Vimeo → YouTube: each Monday the worker (separate repo **embodiedphilosophy/ep-youtube-pipeline**, GitHub Actions)
proposes 5 Studio-Produced talks; staff approve them here; the worker cuts a 15–20 min stretch, makes the thumbnail,
parks the cut on Vimeo; staff review and push to YouTube. Ops only stores, shows and fires.

- Page `/ops/youtube` (`app/ops/youtube/`): tabs This week · Review queue · Published · Skipped. Access `canYouTube` in
  `nav.js` (directors + Team role Media or YouTube, i.e. Jacob and Rebecka). Sidebar: Publishing → YouTube.
- Logic `lib/ops/youtube.js`; records in Neon table `ops_youtube` (`kind` proposal|cut, jsonb `data`; memory without DATABASE_URL).
  Proposal: proposed → producing → ready → published, or skipped. Cut: review ⇄ recutting / rethumbing → publishing → published.
- Worker API `app/api/youtube/*` (Bearer `OPS_PIPELINE_SECRET`, `lib/ops/pipelineauth.js`): `GET /state`, `POST /proposals`,
  `POST /cuts`, `GET /cuts/{id}`, `POST /cuts/{id}/thumbnail` (→ Vercel Blob `youtube/thumbs/`), `POST /cuts/{id}/published`.
  `used_vimeo_ids` = everything approved, skipped, cut or published (untouched proposals may come back).
  `upcoming_programs` = one row per program starting on the Master Schedule in the next 10 weeks.
- A re-cut posts `/cuts` again with the same `proposal_id`: the same cut is updated; any field staff edited (`edited[]`) keeps the staff value.
- Ops fires `repository_dispatch` (`produce`, `thumb`, `publish`) with `GITHUB_PIPELINE_TOKEN`. Re-cut start/end are sent as
  strings because the workflow drops a numeric 0. `thumb` sends the **source** Vimeo ID (the worker grabs frames from it).
- Scheduled release: date + time in New York → `publish_at` in UTC (YouTube keeps it private until then).
- Tasks: one "[yt:week:<date>]" task when proposals arrive and one "[yt:cut:<id>]" per new cut, labelled with directors +
  Media/YouTube people; closed when the week is all decided / the cut is published. Only with the database (not in local tests).
- Env (ep-ops on Vercel): `OPS_PIPELINE_SECRET` (same as the GitHub secret, 24+ chars), `GITHUB_PIPELINE_TOKEN` (fine-grained,
  repo ep-youtube-pipeline, Contents read & write), `BLOB_READ_WRITE_TOKEN` (existing store is fine). Optional
  `GITHUB_PIPELINE_REPO`, `GITHUB_API_BASE` (tests).
- Test: `node scripts/ops-test/youtube.cjs` after `run.sh` (plays the worker; dispatches land in `out/mock.log` as `GITHUB DISPATCH`).

## Ads, PR 4: Audience library (standing, per-campaign results, Practice Report link, "Use in a campaign")

- **Standing is computed, never typed** (`lib/ops/adslibrary.js`, `judge()` and `standingOf()`). For every campaign an audience ran in, its ad set's whole-life total from `ads_results` is judged against **that campaign's own rules** (its target Y = `raise_threshold`, its floor Z = `off_threshold`; with no rules saved the goal's defaults, return 1.5× / cost per lead $1.50 and floors 1.2× / $2.50), but only once the ad set has spent the **minimum spend** over the **minimum days**: *at or above target* (return at least Y, or cost per lead at most Y), *below the floor* (return below Z, or cost per lead above Z or no leads at all: a strike), *below target* (between), *too early* (counts for nothing), *not judged* (Traffic has no rules). **Proven** = at or above target in 2 or more campaigns; **Promising** = once; **Not tested** = neither yet; **Retired** = below the floor 3 times. Retired wins when both are true. A campaign that is still running is judged on what it has so far, so a standing can change as it runs (the update is idempotent).
- **The only human overrides**: **Bring back** (a person, a confirm; only for a Retired audience) forgives the strikes so far and keeps who and when (`ads_audiences.override` = `{ by, at, strikes_forgiven }`, shown on the row and the detail); a strike after that counts again from there, so it can be retired again. Fresh look = 4 calls when nothing needs paging. Code: `lib/ops/adsaccount.js` (reads, memory, rows), `lib/ops/adsaccountmath.js` (sums and returns, no imports, shared with the page), `app/api/ops/ads-account/route.js`, `app/ops/ads/AccountView.js`.
- **Caching.** The Meta part is kept in memory in the server process for **5 minutes**; opening the page again costs no Meta call (several people share it). **Refresh** (POST `{action:'refresh'}`) asks Meta again, **at most once a minute per person** (a second press is answered from memory with "you can ask again in N seconds"; a GET never bypasses the memory). A failed look is remembered for a minute so a rate limit isn't hammered, and the **last good look stays on the page** with the plain reason beside it. On Vercel each server instance has its own memory, so a cold instance makes its own first look.
- **Never throws.** `status.state` is `not_connected` (no key or no ad account: the Settings › Connections wording), `error` (reason class `rate_limit` using the client's `RATE_LIMIT_CODES`, `permission`, `timeout`, `network`, `other`; Meta's own wording is never shown because it can carry ids), `partial` (results or ad sets failed alone, or the paging stopped at its safe limit: a note says which) or `ok`. Only the account call may fail fast (rate limit, key refused): then nothing else is asked.
- **"Made in Ops"** = the campaign's Meta id is in `ads_campaigns.meta_campaign_id` (a `dryrun-…` id never matches). Looked up each time with `adsTablesExist()` then `peekRows`: **with no Ads tables nothing matches and nothing is created**. Everything else is "Not made in Ops" (Ads Manager or Make's Ad Agent).

Totals row = the sum of the shown rows; the blended return is across purchase campaigns only.

## Ads: Creative results (which pictures and which words worked)
A read-only Ads tab (`/ops/ads?view=creative`, after Campaigns; directors and the Ads role, everyone else 403 or sent away). Jake: "the copy and images to me are the most important." It informs a human who decides what to keep, change or retire; it changes nothing in Meta or in any table and never picks creative. No setting, no cron, no new table; Meta's numbers only (real sales from Kit and Circle are not counted, and the page says so).
- **Code**: `lib/ops/adscreative.js` (`creativeView`, pure `judge` and `buildGroups`), `adTotals()` in `lib/ops/adsstore.js` (each ad's lifetime sums from `ads_results`, a plain read that makes no table), `app/api/ops/ads-creative/route.js` (GET only), `app/ops/ads/Creative.js` + `CreativeView.js`. Reads the campaigns that are in Meta (live, paused, sent paused, ended) with their ad sets, creatives, copy sets and ads; draft campaigns and Traffic campaigns are left out (Traffic is counted in a note).
- **What can and cannot be known**: a PICTURE is attributable (one picture per ad, results per ad, summed; the same library picture in several campaigns is one row, an upload is "An uploaded picture"). WORDS are not: `createAdCreative` puts all five copy sets inside every ad and Meta mixes them, and results are kept per ad. So words are judged as the set of texts that ran together (campaigns with exactly the same texts are one set), never one text at a time; the page says so. Judging one text on its own needs separate ads per text (or Meta's per-text breakdown stored by the sync): not built. A pairing is a text set with one picture. Texts show headline and body as saved; the source line (testimonial author, who wrote it) is not shown.
- **Labels** (reused numbers, none invented): "Too early to say" until the row has spent `MIN_SPEND_CENTS` ($50) and has `MIN_PURCHASES` (5 sales) or `MIN_LEADS` (10 leads) (`insightsverify.js`); then "Ahead of the $1.50 line" when return is at least `RULE_DEFAULTS.Purchase.raise_threshold` (1.5), or for lead ads cost per lead at most `RULE_DEFAULTS.Lead.raise_threshold` ($1.50); else "Behind the line". Best and weakest so far are marked when two or more rows can be judged. Sales ads and lead ads are separate lists (a toggle) and are never mixed. Pairings are listed only from $50 spent; the rest are counted.
- **Fairness**: every row shows ads, ad sets, audiences and campaigns behind it, each audience and campaign with its spend, "Ran in only one audience" when so, and two links per campaign that only open things: the campaign page in Ops, and Meta's Ads Manager (`managerUrl`, in a new tab; the link carries the ad account number, as the Account view's links do, never the key). No pause or edit button.
- **Empty words**: no Ads tables ("No ads have been built here yet"), nothing sent to Meta, nothing run yet ("Nothing has run long enough yet"), all rows too early ("Nothing has run long enough yet to judge"), Meta not connected (the last numbers kept are shown, not refreshed).
- **Limits**: reads up to 2000 ads/ad sets/creatives per read; no history tables (PR 90's are not used). Test: `scripts/ops-test/ads-creative.sh` (`ads-creative-api.mjs`, `ads-creative.cjs`; the Meta mock got `/__mode?scale=a,b,c` to size each campaign's results).
